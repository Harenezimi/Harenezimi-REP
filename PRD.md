# PRD: КнигоФорум — платформа для любителей книг

**Версия документа:** 1.0
**Дата:** 26 сентября 2026
**Статус:** MVP реализован

---

## 1. Обзор продукта

**КнигоФорум** — веб-платформа в формате форума для любителей книг, где
пользователи делятся описаниями прочитанных книг и циклов (серий), находят
новые произведения через поиск по жанру и рейтингу, а также могут узнать,
завершён цикл или ещё продолжается. В перспективе платформа предоставит
ссылки на приобретение или скачивание книг.

### 1.1 Проблема

Любителям книг сложно в одном месте:
- найти живое, неформальное описание книги или цикла от таких же читателей;
- отфильтровать произведения по жанру и качеству (рейтингу);
- быстро понять, закончен ли цикл, прежде чем начинать читать;
- получить ссылку, где книгу можно купить или скачать легально.

### 1.2 Решение

Форум, где:
- любой зарегистрированный пользователь может опубликовать запись о книге
  или цикле;
- остальные читатели ищут, фильтруют, оценивают и комментируют эти записи;
- на странице каждой записи есть отдельный блок с внешними ссылками
  (покупка/скачивание), который сообщество наполняет само.

### 1.3 Целевая аудитория

- Активные читатели, которые хотят делиться впечатлениями о книгах;
- Пользователи, выбирающие, что читать дальше, и ищущие ориентир по жанру
  и рейтингу;
- Читатели циклов/серий, которым важно знать статус цикла (завершён/нет)
  перед тем, как вкладываться в чтение.

## 2. Цели и метрики

| Цель | Метрика (для будущих итераций) |
|---|---|
| Пользователи публикуют контент | Число новых записей в неделю |
| Форум помогает выбирать книги | Использование фильтров (жанр/рейтинг/статус) на сессию |

## 3. Объём MVP (реализовано)

### 3.1 Пользователи и аутентификация
- Регистрация по email/имени пользователя/паролю.
- Пароли хранятся в виде bcrypt-хешей, не в открытом виде.
- Вход/выход, сессии на стороне сервера (7 дней жизни куки).
- Личная страница «Мои записи» со списком всех записей пользователя.

### 3.2 Записи о книгах и циклах
Единая сущность **«запись»** описывает либо отдельную книгу, либо цикл:
- Название, автор, описание (свободный текст, мин. 20 символов);
- Один или несколько жанров (выбор из списка + возможность добавить свой);
- Признак «это цикл» (`is_series`);
  - если да — статус цикла: **не завершён** / **завершён**, и опционально
    количество томов;
- Необязательная ссылка на обложку;
- Автор записи и дата публикации отображаются на странице.

### 3.3 Поиск и фильтрация (каталог)
На главной странице доступны:
- Полнотекстовый поиск по названию/автору (частичное совпадение);
- Фильтр по жанру;
- Фильтр по минимальному среднему рейтингу (2★/3★/4★);
- Фильтр по статусу: отдельная книга / цикл не завершён / цикл завершён;
- Сортировка: сначала новые / по рейтингу / по названию.

Все фильтры комбинируются и передаются через query-параметры URL
(`/?genre=1&status=completed&sort=rating`), что делает результаты поиска
доступными по прямой ссылке.

### 3.4 Рейтинги
- Авторизованный пользователь может поставить оценку от 1 до 5 звёзд
  каждой записи;
- Повторная оценка обновляет предыдущую (одна оценка на пользователя на
  запись);
- На странице записи и в каталоге отображается средний рейтинг и число
  проголосовавших.

### 3.5 Комментарии
- Авторизованные пользователи оставляют текстовые комментарии под записью;
- Комментарии отображаются в хронологическом порядке с именем автора и
  датой.

### 3.6 Задел на будущее: ссылки на покупку/скачивание
Реализована базовая версия, которую в дальнейшем предстоит развить:
- На странице записи есть блок **«Где почитать»**;
- Любой авторизованный пользователь может добавить ссылку с типом
  **«Купить»** или **«Скачать»**, названием источника (например, «Litres»)
  и URL;
- В базе данных уже заложено поле `is_approved` для будущей модерации
  ссылок перед показом (в MVP все ссылки показываются сразу, без проверки).

### 3.7 Интерфейс
- Отдельные страницы: каталог, страница записи, форма создания записи,
  вход, регистрация, профиль, 404/500;
- Адаптивная вёрстка (мобильные экраны поддерживаются);
- Оформление в «книжной» цветовой палитре (тёплые бежевые/коричневые
  тона).

## 4. Пользовательские сценарии (User Stories)

1. **Как читатель**, я хочу зарегистрироваться, чтобы иметь возможность
   публиковать записи, оставлять оценки и комментарии.
2. **Как читатель**, я хочу опубликовать описание прочитанной книги или
   цикла, чтобы поделиться впечатлением с сообществом.
3. **Как читатель**, я хочу указать, что книга — часть цикла, и отметить,
   завершён ли цикл, чтобы предупредить других о риске «зависшей» серии.
4. **Как читатель**, я хочу искать книги по жанру и минимальному рейтингу,
   чтобы быстро найти что почитать.
5. **Как читатель**, я хочу видеть, завершён цикл или нет, прямо в
   результатах поиска (бейдж на карточке), не открывая каждую запись.
6. **Как читатель**, я хочу оценить книгу и прочитать/оставить комментарии
   других, чтобы принять решение о чтении.
7. **Как читатель**, я хочу видеть (и в будущем — добавлять) ссылки, где
   книгу можно купить или скачать, не покидая форум.

## 5. Архитектура и технологии

| Слой | Технология | Примечание |
|---|---|---|
| Backend | Node.js + Express | Серверный рендеринг (SSR) |
| Шаблоны | EJS | Частичные шаблоны (header/footer/errors) |
| База данных | SQLite (`better-sqlite3`) | Файл БД, без отдельного сервера СУБД |
| Сессии | `express-session` + `connect-sqlite3` | Хранение сессий в SQLite |
| Пароли | `bcryptjs` | Хеширование |
| Валидация | `express-validator` | Валидация форм на сервере |
| Стили | Чистый CSS | Без фреймворков |

### 5.1 Структура проекта

```
src/
  app.js                — точка входа, конфигурация Express
  db/
    schema.sql          — DDL всех таблиц
    index.js            — подключение к SQLite, инициализация схемы
    queries.js          — весь доступ к данным (модели/запросы)
    seed.js             — демо-данные для разработки
  middleware/auth.js     — attachUser, requireAuth
  routes/
    auth.js              — регистрация / вход / выход
    entries.js            — каталог, поиск, CRUD записей, комментарии,
                             рейтинги, внешние ссылки, профиль
  views/                  — EJS-шаблоны по разделам (auth, entries, users, errors)
public/css/style.css      — стили
```

### 5.2 Модель данных

```
users            id, username, email, password_hash, created_at

entries          id, user_id → users, title, author, description,
                 is_series, series_status ('ongoing'|'completed'|NULL),
                 volumes_count, cover_url, created_at, updated_at

genres           id, name

entry_genres     entry_id → entries, genre_id → genres   (многие-ко-многим)

ratings          id, entry_id → entries, user_id → users,
                 rating (1..5), UNIQUE(entry_id, user_id)

comments         id, entry_id → entries, user_id → users,
                 content, created_at

external_links   id, entry_id → entries, user_id → users,
                 link_type ('purchase'|'download'), label, url,
                 is_approved (задел под модерацию), created_at
```

Ключевое архитектурное решение: **книга и цикл — одна и та же сущность**
(`entries`) с флагом `is_series`, а не две разные таблицы. Это упрощает
поиск, фильтрацию и рейтинги, поскольку не нужно объединять два разных
типа сущностей в выдаче каталога.

### 5.3 Маршруты (API поверхности, серверный рендеринг)

| Метод | Путь | Назначение | Доступ |
|---|---|---|---|
| GET | `/` | Каталог с поиском/фильтрами | Публичный |
| GET/POST | `/register` | Регистрация | Публичный |
| GET/POST | `/login` | Вход | Публичный |
| POST | `/logout` | Выход | Авторизован |
| GET | `/entries/new` | Форма создания записи | Авторизован |
| POST | `/entries` | Создание записи | Авторизован |
| GET | `/entries/:id` | Страница записи | Публичный |
| POST | `/entries/:id/comments` | Добавить комментарий | Авторизован |
| POST | `/entries/:id/rating` | Поставить/обновить оценку | Авторизован |
| POST | `/entries/:id/links` | Добавить ссылку покупки/скачивания | Авторизован |
| GET | `/profile` | Мои записи | Авторизован |

## 6. Нефункциональные требования

- **Простота развёртывания**: SQLite вместо отдельного сервера БД — проект
  запускается локально в три команды (`npm install`, `npm run seed`,
  `npm start`).
- **Безопасность паролей**: bcrypt-хеширование, пароли никогда не хранятся
  и не логируются в открытом виде.
- **Валидация ввода**: серверная валидация всех форм (длина полей,
  формат email/URL, обязательные поля).
- **Адаптивность**: интерфейс корректно отображается на мобильных экранах.
- **Локализация**: интерфейс и контент — на русском языке.

## 7. Вне рамок MVP (сознательно не реализовано)

- Загрузка файлов обложек (сейчас только по ссылке);
- Модерация контента и ролей модератора/администратора;
- Проверка/модерация ссылок на покупку/скачивание перед публикацией
  (поле `is_approved` заложено, но не используется в интерфейсе);
- Интеграция с конкретными магазинами и библиотеками (Litres, Bookmate,
  Amazon и т.п.) — сейчас пользователи вставляют произвольные ссылки;
  реализация функции загрузки заявленна в качестве будущей задачи по
  первоначальному запросу;
- Пагинация каталога (сейчас выводятся все записи целиком);
- Полнотекстовый поиск (используется `LIKE`, а не FTS5);
- Личные списки чтения / статусы «читаю» / «прочитано» / «хочу прочитать»;
- Push/email-уведомления;
- Публичное развёртывание (продакшен-хостинг, домен, HTTPS) — проект
  передан как исходный код для локального запуска или самостоятельного
  деплоя.

## 8. Дорожная карта (следующие итерации)

1. **Модерация ссылок на покупку/скачивание** — включить поле
   `is_approved`, добавить роль модератора, скрывать неподтверждённые
   ссылки от обычных пользователей.
2. **Партнёрские интеграции** — API/партнёрские ссылки с конкретными
   магазинами и библиотеками (Litres, Bookmate, официальные издательства).
3. **Загрузка обложек файлом** вместо/в дополнение к ссылке.
4. **Личные списки чтения** — «читаю сейчас», «прочитано», «хочу прочитать»,
   как отдельная сущность, привязанная к пользователю и записи.
5. **Пагинация и полнотекстовый поиск** (SQLite FTS5) — при росте числа
   записей.
6. **Роли и модерация контента** — жалобы на записи/комментарии, бан
   пользователей.
7. **Продакшен-деплой** — вынос на хостинг (Render/Railway/Fly.io),
   собственный домен, HTTPS, миграция при необходимости на управляемую
   СУБД (Postgres) при росте нагрузки.
8. **Аналитика использования** — метрики из раздела 2 (использование
   фильтров, число записей/комментариев/ссылок в неделю).

## 9. История решений (из обсуждения с заказчиком)

| Вопрос | Решение |
|---|---|
| Формат результата на первом этапе | Полноценное full-stack приложение (не прототип и не только ТЗ) |
| Ссылки на покупку/скачивание | Заложить место в архитектуре сразу (таблица `external_links`, базовый UI), полноценную интеграцию с магазинами — отложить на будущее |
| Формат сущности книга/цикл | Одна таблица `entries` с флагом `is_series` вместо двух разных сущностей |
| Стек | Node.js/Express/SQLite — как самодостаточное решение без внешних зависимостей от облачных БД |

## 11. Открытые вопросы

- Нужна ли премодерация вообще для новых записей (не только ссылок), или
  форум остаётся полностью открытым для публикации?
- Какие конкретно магазины/библиотеки приоритетны для будущей интеграции
  ссылок на покупку/скачивание?
- Нужна ли многоязычность интерфейса, помимо русского?
- Каким будет масштаб аудитории — определяет, когда переходить с SQLite
  на управляемую СУБД (Postgres/MySQL).
